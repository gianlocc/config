## Recording work milestones (work-book)

When we complete a meaningful work milestone — a feature shipped, a hard bug fixed, a tricky problem solved, an important design decision made, a release cut, an investigation concluded — record it WITHOUT being asked by running:

```
/Users/gianlo_exa/Develop/work-book/bin/workbook milestone "<one concise past-tense sentence>"
```

Guidelines: one milestone per genuine accomplishment (not routine edits); phrase it for a performance review (what was achieved and why it mattered); run it quietly as a normal tool call and mention briefly that you logged it. Do not record trivial steps, questions, or work in progress.
